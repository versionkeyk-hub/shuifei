## 四、★ 两种修改的区别（重要！）

这是整个系统最关键的概念，必须理解清楚：

### 1. 数据修改 — 在网站后台改，保存即生效

**改什么：** 产品名称、厂家、登记证号、图片、pH值、农药禁忌、混配标记（含铜/杀菌剂/建议单用等）、混配关系（禁混/谨慎混配）

**怎么改：** 登录管理后台 → 产品管理/农药管理 → 编辑 → 保存

**效果：** 直接写入 Supabase 云数据库，刷新页面即生效。**不用重新部署。**

**涉及文件：** 不涉及任何文件改动，数据存在数据库里。

### 2. 框架修改 — 改代码文件，必须重新部署

**改什么：** 网页界面布局、搜索逻辑、混配判断规则代码、新功能开发、样式调整

**怎么改：** 修改本地文件（app.js / admin.html / style.css / index.html 等）→ 重新打包上传到 Netlify

**效果：** 新代码上线，但静态数据文件（data/products.js 等）里的是**旧数据**。

## 五、★ 重新部署时云端和本地的矛盾（核心问题）

### 矛盾在哪

你在后台改了产品信息 → 保存在 Supabase 云端。
然后你改了框架代码 → 需要重新上传到 Netlify。
上传的文件夹里，`data/products.js` 还是**很久以前的旧数据**。

但是——**这不冲突，云端数据优先。**

### 页面加载时的数据流

```
1. 浏览器加载网页文件（Netlify 上的）
   → data/products.js 被读取（旧数据，填入 COMPANY_PRODUCTS）
   → data/pesticide_extras.js 被读取（旧数据，填入 PESTICIDE_EXTRAS）
   → data/pesticides.js 被读取（6705条农药，填入 PESTICIDES）

2. db.js 执行 DB.load()
   → 从 Supabase 拉取最新数据
   → 完全覆盖 COMPANY_PRODUCTS（产品：云端完全替换静态文件）
   → 合并覆盖 PESTICIDE_EXTRAS（农药扩展：云端优先，静态文件补充云端没有的）
   → 按 component 替换 PESTICIDES 中被修改过的条目（农药覆盖表）
   → 加载 COMPATIBILITY 混配关系表（农药成分 ↔ 产品）

3. 页面渲染用的是云端最新数据
```

**结论：你在后台改的数据不会丢失，重新部署也不影响。静态文件只是兜底回退，云端不可用时才用。**

### 什么时候需要"同步全部到云端"

只有一种情况：**你直接修改了 data/ 目录下的静态文件**（比如在 products.js 里手动加了一个新产品，或在 pesticides.js 里改了 flags），并且重新部署了。

这时静态文件有新数据，但云端还是旧的。你需要：

1. 部署完成后，打开管理后台
2. 进入"修改/导出数据"标签页
3. 点 **"同步全部静态数据到云端"** 按钮
4. 等待提示"同步完成"

这会把静态文件的最新数据一次性推送到 Supabase，之后云端就是最新的了。

**注意：这个按钮会覆盖云端已有的数据。如果你在后台改了数据还没同步到静态文件，点这个按钮会把云端数据覆盖回静态文件的版本。**

### 推荐的修改方式

| 要改什么 | 在哪改 | 要重新部署吗 | 要同步云端吗 |
|----------|--------|-------------|-------------|
| 产品信息（名称/厂家/图片等） | 后台 → 产品管理 | 否 | 否 |
| 农药 pH / 禁忌 / 混配标记 | 后台 → 农药管理 → 编辑 → 保存 | 否 | 否 |
| 混配关系（禁混/谨慎混配） | 后台 → 农药管理/产品管理 → 编辑 → 保存 | 否 | 否 |
| 农药注意事项/用法/解决问题 | 后台 → 农药管理 → 编辑 → 保存 | 否 | 否 |
| 加新产品 | 后台 → 产品管理 → 添加 | 否 | 否 |
| 加新农药 | 后台 → 农药管理 → 添加 | 否 | 否 |
| 网页界面/布局 | 改 index.html / style.css | **是** | 否 |
| 搜索/混配逻辑 | 改 app.js | **是** | 否 |
| 后台界面 | 改 admin.html | **是** | 否 |
| 数据文件本身（特殊需求） | 改 data/*.js | **是** | **是**（部署后点同步） |

**一句话总结：数据在后台改，代码在文件改。后台改完即生效，代码改完要部署。两者不冲突。**

## 七、混配规则要点

### 禁混（绝对不能混）
- 除草剂 + 任何肥料
- 铜制剂 + 氨基酸产品（络合反应）
- 铜制剂 + 腐殖酸产品（络合沉淀）
- 杀菌剂/铜制剂 + 微生物菌剂（杀菌）
- 氯溴异氰尿酸 + 氨基酸/腐殖酸/含磷产品（沉淀失效）

### 建议单用
- 氯溴异氰尿酸：氧化性强，与其他肥料混配易降低效果，建议单独使用，间隔3-5天
- 给任何农药加 `suggest_alone: true` 标记 → 系统自动返回"建议单用"

### 需谨慎
- 含铜产品 + 代森类/硫制剂/福美双/多菌灵
- 无机铜 + 所有肥料

### 需间隔
- 强酸产品 + 碱性农药（酸碱中和）
- 强碱产品 + 酸性农药
- 含钙 + 含磷（磷酸钙沉淀）
- 农药标明"不能与碱性物质混用" + 产品pH>7.5

## 八、混配标记（flags）说明

在后台"农药管理"标签页编辑农药时，可以勾选以下标记（已合并原"农药扩展"tab的所有标记）：

| 标记 | 含义 | 触发效果 |
|------|------|----------|
| `is_copper` | 含铜 | 与代森类/硫制剂需谨慎，与氨基酸/腐殖酸禁混 |
| `is_inorganic_copper` | 无机铜 | 与所有肥料需谨慎 |
| `is_organic_copper` | 有机铜 | 同含铜规则 |
| `is_dithiocarbamate` | 代森类 | 与含铜产品需谨慎 |
| `is_sulfur` | 硫制剂 | 与含铜产品需谨慎 |
| `is_thiram` | 福美双 | 与含铜产品需谨慎 |
| `is_benzimidazole` | 多菌灵类 | 与含铜产品需谨慎 |
| `is_fungicide` | 杀菌剂 | 与微生物菌剂禁混 |
| `is_chloroisobromine` | 氯溴异氰尿酸 | 与氨基酸/腐殖酸/含磷禁混 |
| `suggest_alone` | 建议单用 | 与其他产品返回"建议单用"，间隔3-5天 |
| `no_alkali_mix` | 不能与碱性物质混用 | 产品pH>7.5时需间隔 |
| `is_strong_base` | 强碱 | pH>10 |
| `is_strong_acid` | 强酸 | pH<4 |

## 十二、混配联动功能说明（核心功能）

### 设计原理

混配联动是本网站的核心功能。通过一张 `compatibility` 表实现农药侧和产品侧的双向自动联动：

```
compatibility 表
┌────────────────────┬────────────┬──────────┬────────┐
│ pesticide_component │ product_id │ product_name │ status │ reason │
├────────────────────┼────────────┼──────────┼────────┤
│ 氢氧化铜            │ aomei      │ 傲美     │ forbidden │ 铜与氨基酸络合 │
│ 氢氧化铜            │ aotu       │ 傲土     │ caution   │ 铜与钙反应   │
└────────────────────┴────────────┴──────────┴────────┘
```

### 双向联动

- **农药侧编辑：** 在"农药管理"编辑某农药时，可以选择"禁混产品"和"谨慎混配产品"（从产品列表下拉选择）
- **产品侧编辑：** 在"产品管理"编辑某产品时，可以输入"禁混成分"和"谨慎混配成分"（输入农药成分名）
- **自动同步：** 在农药侧添加的禁混产品 → 打开产品编辑时自动看到该成分在禁混列表中
- **用户端展示：** 搜索农药时，混配结果优先使用 compatibility 表的判断；产品详情弹窗中显示禁混/谨慎混配成分列表

### 优先级

`compatibility 表（手动指定）` > `规则引擎（pH/成分/flags自动判断）`

手动指定的关系优先于规则引擎。如果 compatibility 表中某对农药+产品标记为"禁混"，即使规则引擎认为可混，也返回禁混。
